首先，我们需要将JSX转为JS，我们利用babel将JSX转为createElement函数的调用，于是我们得到了element元素；

接着我们通过render函数，将element转为dom元素，挂载在React容器内。

> 为什么不一次性将JSX转为dom元素呢？
> React 可以适配多种渲染器，比如浏览器、Node、Native等，因此我们需要统一的结构描述React元素（业界称为 Render 阶段），再由渲染器将React Element转为适配不同容器的元素，
>  例如浏览器中, 会将React Element 转为 dom元素（业界称为 commit 阶段）。

createElement 函数本身很简单 将babel传入的参数转移为element结构即可：
> 其中babel会深度遍历，将children也转为createElement，所以children本身就是element,除了纯文本；

```js
const createElement = (type,props,...children) => {
    const createChildren = (child)=>{
        // 若是纯文本
        if (typeof child === 'string'){
           return {
             type: "TEXT_ELEMENT",
                props: {
                    nodeValue: child,
                }
            }
        } else {
            return child;
        }
    }
    return {
        type,
        props:{
            ...props,
            children:children.map(child => createChildren(child))
        }
    }
}
```

下一步我们实现 `render` 函数， render的目标是将element 转为dom 元素，并且挂载在container上，用简单的递归实现：
```js
const render = (element,container)=>{
    // 创建dom元素
    const dom = document.createElement(element.type);
    const {children, ...props} = element.props;
    // 将element 的 props assign 给 dom
    Object.keys(props).forEach((prop) => {
        dom[prop] = props[prop];
    });
    // 递归挂在子元素
    children.forEach(child => {
        render(child,dom);
    });
    // 将dom挂载在container上
    container.appendChild(dom);
}
```

到此为止，最简单的React应用已经完成，不过它存在一些问题：
1. render函数采用递归，不可中断的，这意味着，执行render操作时，主线程阻塞不可交互；

解决这个问题我们需要和浏览器交互，浏览器api `requestIdleCallback` 可以在空闲时间调用传入的回调函数，并且向回调函数传入参数deadline，deadline包含了当前时间片的信息，会告诉我们是什么时候时间片结束；

> React doesn’t use requestIdleCallback anymore. Now it uses the scheduler package. But for this use case it’s conceptually the same.

```js
const workLoop = (deadline) => {
    // 开始执行任务
    let shouldYield = false;
    while (!shouldYield && nextUnitOfWork) {
        nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
        shouldYield = deadline.timeRemaining() < 1;
    }
    // 时间片用完时 注册下一个空闲时间执行任务
    requestIdleCallback(workLoop);
}
```

下一步 我们需要将原来的render 函数拆分成任务单元 `unitOfWork`，并且实现 `performUnitOfWork` 函数，该函数执行任务单元，并且返回下一个任务单元；

> 🧐 猜测： 将element 生成为一个虚拟节点 就是 一个 unitWork ， performUnitOfWork 将 当前element 转为 虚拟节点， 并且返回下一个element

下面我们需要介绍新概念——Fiber，Fiber 依据element树构造Fiber树，便于performUnitOfWork更容易找到 `nextUnitOfWork`，也用于存储其他 ReactNode 信息。

目前我们 Fiber 节点只需要存储节点之间的关系：parent、child（first child）、siblings；

```ts
interface Fiber {
  /** 元素类型 */
  type: string;
  /** 元素属性 包含children */
  props: { [key: string]: any };
  /** 对应dom节点 */
  dom?: HTMLElement | null;
  /** 第一个子元素 */
  child?: Fiber | null;
  /** 父元素 */
  parent: Fiber | null;
  /** 兄弟元素 */
  sibling?: Fiber | null;
}
```

UnitOfWork 的任务是：
1. 将当前fiber 节点转为dom 节点，并挂载；
2. 将子元素（element）转为fiber 节点；（不包含孙子节点）；
3. 返回下一个任务单元（即fiber节点）；
寻找下一个任务单元符合dfs的顺序，即：
* 优先找第一个子节点；
* 没有子节点，找兄弟节点；
* 没有兄弟节点，找父节点的兄弟节点；
* 直到没有父节点，结束；

```js
const performUnitOfWork = (fiber) => {
  if (!fiber.dom){
    fiber.dom = createDom(fiber);
  }
  // 挂载当前节点
  if (fiber.parent){
    fiber.parent.dom.appendChild(fiber.dom);
  }
  const prevFiber = null;
  fiber.props.forEach(child => {
    const newFiber = {
      type: child.type,
      props: child.props,
      parent: fiber,
      dom: null,
    }
    if (prevFiber){
      prevFiber.sibling = newFiber;
    }else{
      fiber.child = newFiber;
    }
    prevFiber = newFiber;
  })
  return dfs(fiber)
}
```

`render`函数只需要创建第一个任务单元(Fiber根节点)，然后调用`workLoop`函数即可：
```js
const render = (element,container)=>{
    const rootFiber = {
        type: element.type,
        props: element.props,
        parent: null,
        dom: null,
    }
    container.appendChild(rootFiber.dom);
    nextUnitOfWork = rootFiber;
    requestIdleCallback(workLoop);
}
```
到此为止，我们已经实现了一个**可中断的**React应用，不过它还存在一个问题：在渲染过程中会向用户展示渲染的中间态。


向用户展示渲染的中间态，是用户体验不友好的，这种情况下，用户可能会与未加载完的页面进行交互；因此我们需要将渲染和挂载dom的操作分开：
- 渲染：将element 转为fiber 节点, 挂载在fiber树上， 生成children的fiber节点；这个过程是可以中断的；
- 提交：将fiber 节点对应的dom节点挂载到dom树上，这个过程是不可中断的；

删除performUnitOfWork中下面代码

```
 if (fiber.parent){
    fiber.parent.dom.appendChild(fiber.dom);
  }
```

修改render 函数，render工作完成时，调用 commit 函数：
```js
const render = (element,container)=>{

        type: element.type,

        parent: null,
        dom: null,
    }
```

`commit`递归将fiber节点对应的dom节点挂载到dom树上：
```js

        return;

    const domParent = fiber.parent.dom;
    domParent.appendChild(fiber.dom);
    commit(fiber.child);
    commit(fiber.sibling);          
}
```
目前为止我们将React应用分为可中断的render过程和不可中断的commit过程。

接下来我们实现节点更新和删除，为了提升性能，更新/删除并不会将整个dom树重新渲染，而是标记需要变更的节点，然后在commit阶段部分变更。

`reconcileChildren`中，对比上一次渲染的 fiber 节点 和 当前element的差异，根据类型判断：
- 类型相同：则仅需更新属性，打上 `UPDATE`的tag；
- 类型不同：
  - 上一次渲染的fiber节点存在：则给旧的fiber 节点打上 `DELETE` 的 tag， 并且， 由于 我们新commit的fiber 树没有需要删除的旧fiber 节点，我们需要 新增`deletion`数组维护它；
  - 当前element存在：则创建新的fiber节点，并且打上`REPLACEMENT`的tag；

```js

            oldFiber.type === element.type;

        if (sameType){
            const newFiber = {
                type: element.type,
                props: element.props,
                parent: fiber,
                dom: oldFiber.dom,
                alternate: oldFiber,
                effectTag: "UPDATE",
            }
        }
        if (element && !sameType){
            const newFiber = {
                type: element.type,
                props: element.props,
                parent: fiber,
                dom: null,
                alternate: null,
                effectTag: "REPLACEMENT",
            }
        }
        if (oldFiber && !sameType){
            oldFiber.effectTag = "DELETION";
            deletion.push(oldFiber);
        }
        if (prevFiber){
            prevFiber.sibling = newFiber;

            fiber.child = newFiber;
        }
        prevFiber = newFiber;
        oldFiber = oldFiber?.sibling;

    }
}
```

接下来我们来实现functional component， 例如：

```jsx
function App(){
    return <div>
        <h1>Hello World</h1>
        <p>Hello World</p>
    </div>
}
```

functional component 和 传统元素的差异在：
- 组件本身不会转为element，而是函数组件的返回值转为element；
- 组件本身没有对应的dom元素；

因此有2点需要兼容：
1. render阶段，reconcileChildren前，根据element类型不同，采用不同方式获取子节点；

```js
if (element.type === "function"){
    const children = [fiber.type(fiber.props)];
    fiber.props.children = children;
    reconcileChildren(fiber);
}else{
    if (!fiber.dom){
        fiber.dom = createDom(fiber);
    }
    reconcileChildren(fiber);
}
```

2. commit 阶段，删除type为function的fiber节点对应的dom节点时，由于它没有对应的dom节点，所以需要删除它最近的子节点（递归）；及其function的fiber节点挂载时，需要向上追溯到最近的有dom的父节点。

接下来我们实现 useState hook， useState 用于保存组件的状态：
- 首次调用时，传入初始化值；
- useState 返回当前状态 state 以及更新状态的函数 setState；

每个 fiber 可以挂载多个hooks，且每次渲染时，hooks的调用顺序一致，每个hook 存储的状态相互隔离；因此我们还需要在Fiber中新增属性存储当前Fiber节点调用的hooks:


```ts
interface Fiber {
  /** 元素类型 */
  type: string;
  /** 元素属性 包含children */
  props: { [key: string]: any };
  /** 对应dom节点 */
  dom?: HTMLElement | null;
  /** 第一个子元素 */
  child?: Fiber | null;
  /** 父元素 */
  parent: Fiber | null;
  /** 兄弟元素 */
  sibling?: Fiber | null;
  /** 上一次渲染的fiber节点 */
  alternate?: Fiber | null;
  /** 当前Fiber节点调用的hooks */
  hooks?: Hook[];
}

interface Hook {
  /** 当前状态 */
  state: any;
  /** 更新队列 */
  queue: any[];
}
```


首先我们需要全局变量确认当前被调用的hook是哪一个：
- wipFiber：当前正在渲染的fiber节点；
- hookIndex：当前被调用的hook的索引；

```js
const useState = (initial)=>{
  // find the hook we last called in this fiber
  const oldHook = wipFiber.alternate?.hooks?.[hookIndex];
  // new wip hook
  const hook = {
    state: oldHook?.state ?? initial,
    queue: []
  }

  // 重新计算state
  const actions = oldHook?.queue?? [];
  actions.forEach(action => {
    hook.state = action(hook.state);
  })

  const setState = (action)=>{
    // 将action放入更新队列
    hook.queue.push(action);
    // 重新渲染
    wipRoot = {
      dom: currentRoot.dom,
      props: currentRoot.props,
      alternate: currentRoot,
    }
    nextUnitOfWork = wipRoot;
    requestIdleCallback(workLoop);
  }

  wipFiber.hooks.push(hook);
  hookIndex++;

  return [
    state,
    setState
  ]
}
```
